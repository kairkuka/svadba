# Старт работ: iOS и Android приложения

Дата: 14 июля 2026  
Фокус: mobile-first MVP

## 1. Базовое решение для старта

Для первого релиза идем от модели:

- одно приложение для iOS и Android;
- внутри две роли: клиент и подрядчик;
- админка остается в вебе;
- Bitrix/Aspro используются как основа backend, админки, контента и SEO-витрины;
- мобильные приложения работают через API;
- mobile-first UX важнее веб-витрины.

## 2. Что нужно сделать первым

### 2.1. Принять продуктовые решения

Нужно подтвердить:

1. Одно приложение с ролями или два отдельных приложения.
2. Кроссплатформенный стек или нативная разработка.
3. Входит ли чат в первый MVP.
4. Входит ли календарь бронирования в первый MVP.
5. Входит ли калькулятор в первый MVP или идет во второй релиз.
6. Нужны ли русский и казахский языки на старте.
7. Какие города запускаются первыми.
8. Какие категории обязательны для первого каталога.

Первый пакет приложения:

## 3. Sprint 0

Цель: подготовить проект к разработке без неопределенностей.

Результаты Sprint 0:

- утвержден MVP;
- утверждена карта экранов;
- утвержден стек;
- утверждена архитектура API;
- утверждена модель ролей;
- утверждены основные сущности;
- создан прототип ключевых сценариев;
- подготовлена структура backlog;
- определены риски и открытые вопросы.

Продолжительность: 1-2 недели.

## 4. Первый MVP backlog

### Эпик 1. Авторизация и роли

- Splash screen.
- Onboarding.
- Выбор города.
- Выбор роли.
- Регистрация клиента.
- Регистрация подрядчика.
- Вход.
- Выход.
- Согласие на обработку данных.

### Эпик 2. Каталог клиента

- Главная клиента.
- Категории.
- Каталог подрядчиков.
- Поиск.
- Фильтры.
- Сортировка.
- Карточка подрядчика в списке.
- Детальная карточка подрядчика.
- Галерея портфолио.

### Эпик 3. Заявки

- Форма заявки.
- Отправка заявки.
- Список заявок клиента.
- Деталка заявки клиента.
- Входящие заявки подрядчика.
- Деталка заявки подрядчика.
- Смена статуса заявки.
- Уведомления по заявке.

### Эпик 4. Подрядчик

- Главная подрядчика.
- Профиль подрядчика.
- Создание профиля.
- Создание услуги.
- Редактирование услуги.
- Портфолио.
- Загрузка фото.
- Статус модерации.
- Причина отклонения.

### Эпик 5. Избранное

- Добавить в избранное.
- Удалить из избранного.
- Список избранного.
- Переход в карточку.
- Скрытая/недоступная карточка.

### Эпик 6. Календарь и бронь

- Календарь подрядчика.
- Отметить занятую дату.
- Запросить дату клиентом.
- Подтвердить бронь.
- Отклонить бронь.

### Эпик 7. Чат

- Новый статус заявки.
- Новый запрос брони.
- Новое сообщение.
- Результат модерации.
- Аналитика открытия карточки.
- Аналитика CTA.
- Аналитика заявки.

### Эпик 9. Безопасность и жалобы

- Защита API.
- Доступ по ролям.
- Жалоба на карточку.
- Жалоба на отзыв.

Можно перенести во второй этап:

- сложный калькулятор свадьбы;
- чек-лист с напоминаниями;
- персонализированный подбор;
- вложения в чате;
- платежи;
- платные продвижения;
- расширенная аналитика подрядчика;
- мобильная админка;
- сложная CRM-интеграция.

Для запуска MVP нужны:

- product/проектный менеджер;
- UX/UI-дизайнер;

- QA;

- контент-менеджер;
- юрист по персональным данным и пользовательским документам.

## 7. Первые артефакты

Нужно подготовить:

- интерактивный прототип;
- UI-kit;
- backend API contract;
- ERD или схема сущностей;
- backlog;
- оценка MVP;
- план тестирования;

- материалы для App Store и Google Play.

## 8. Главные риски на старте

| Риск | Что сделать |
| --- | --- |
| Нет решения по стеку | Выбрать стек до оценки разработки |
| Чат раздувает MVP | Зафиксировать MVP-вариант чата или временно заменить заявкой + WhatsApp |
| Bitrix не готов как API-backend | Спроектировать API-слой отдельно |
| Нет UX/UI-прототипа | Начать с карты экранов и clickable-прототипа |
| Нет данных для калькулятора | Не включать сложный калькулятор в первый MVP |
| Не готова юридическая база | Подготовить privacy policy, terms и согласия до публикации |
| Нет тестовых устройств | Составить матрицу устройств iOS/Android |
